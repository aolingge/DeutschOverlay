# 德语实时字幕桌面应用设计

日期：2026-09-24
状态：待用户审阅

## 目标与使用场景

为当前这台 Windows 11 电脑制作一个可启动的 EXE 应用。它从电脑正在播放的声音生成字幕，主要用于玩德语游戏时学习德语，也用于看英语或中文视频。字幕固定在屏幕下方，不需要依赖游戏或视频本身提供字幕。

| 声音语言 | 默认显示 | 开启原文对照后 |
| --- | --- | --- |
| 德语 | 德语转写 | 仍显示一行德语，避免重复 |
| 英语 | 德语译文 | 德语译文及较小的英语原文 |
| 中文 | 德语译文 | 德语译文及较小的中文原文 |

首个实际验收场景是无边框全屏的德语游戏。英语视频和中文视频随后分别验证翻译路径。首版只捕捉选定播放设备的电脑声音，不捕捉麦克风，也不按应用进程过滤音频。

## 已确认的产品决定

- 字幕条固定在用户选择的位置；有语音时显示，无语音时隐去。默认位置为屏幕下方居中，默认在最后一句字幕结束 3 秒后淡出；淡出时间可设置。
- 游戏中采用无边框全屏。锁定后的字幕条置顶、鼠标穿透、不抢键盘焦点；解锁后可以拖动、调整宽度和字体大小，并保存位置。
- 默认只显示德语。全局快捷键或托盘菜单可切换原文对照、显示或隐藏字幕条、锁定或解锁语言。
- 自动识别德语、英语和中文；用户可以手动锁定其中一种语言。手动锁定优先于自动识别。
- 本地与在线模式可切换。本地为启动默认值。在线服务只有用户主动配置并启用后才发送音频。
- 目标是说话结束后约 2–3 秒出现稳定字幕；这是一项需要在真实游戏中测量和优化的目标，不是每句的保证值。

## 方案选择

采用 Python、PySide6 和 Windows WASAPI 环回录音实现首版。Python 便于接入本地语音与翻译模型；PySide6 提供无边框、置顶和输入穿透窗口能力；WASAPI 可以捕捉选定播放设备上的混合声音。与 C# 原生界面加独立推理进程相比，这一方案的首版集成较少。游戏覆盖行为和显卡推理兼容性仍由第一阶段实测决定。

一条声音只走当前选定的处理模式：

```text
电脑播放设备 ──WASAPI 环回──> 音频缓冲/语音片段
                                      │
                        ┌─────────────┴─────────────┐
                        │                           │
                  本地识别与翻译                在线识别与翻译
                        │                           │
                        └─────────────┬─────────────┘
                                      │
                         字幕状态与重复片段合并
                                      │
                             置顶字幕条 / 托盘控制
```

处理模块通过统一的字幕事件交付检测语言、原文、德语文本、开始与结束时间以及“临时/确定”状态。界面只消费字幕事件，不直接控制模型。模式切换时结束旧音频会话、清空未确定片段，然后启动新会话，避免两种模式同时处理同一段声音。

### 音频与字幕

- 枚举播放设备，用户选择一个；默认使用当前系统默认播放设备。设备切换、断开或音频格式变化时暂停识别并提示重新连接，不展示旧字幕作为新结果。
- 连续缓冲声音并按语音活动切成短片段；静音和过短噪声不送入识别。对游戏音效、背景音乐和多人重叠说话，只承诺尽力识别，不承诺逐人分离。
- 临时识别文字可以用较淡样式提前出现；句子确定后替换为稳定字幕。翻译只对足够稳定的原文执行，避免每个字变化都触发翻译和闪烁。
- 对同一片段使用稳定 ID 合并更新，限制最多两行德语；文字过长时分段展示。字幕条隐藏不等于停止声音处理，用户可用快捷键暂停识别。

### 本地模式

- 首个识别基线采用多语言 `faster-whisper` 的 small 模型，并先在本机 GPU 上运行；GPU 初始化失败时明确提示，可手动选择 CPU 模式。先测真实性能，再决定是否改用更大模型。
- 德语识别结果直接显示。英语和中文识别结果分别经过本地德语翻译。首个翻译基线采用 Helsinki-NLP 的 `opus-mt-en-de` 和 `opus-mt-zh-de`，经 CTranslate2 加载；翻译质量与速度在验收片段上记录。若中文直译质量不足，实施阶段可以按同一接口替换模型，并在变更记录中说明。
- 本地模型放在应用数据目录或发行包的独立模型目录，不嵌进单个 EXE。首次使用时由应用展示下载大小、来源和许可证并取得用户操作；下载完成后离线可用。缺模型时给出安装入口，不默默切换到在线模式。

### 在线模式

- 首个在线供应商候选为 Microsoft Azure Speech：持续语言识别、德语译文和原文都通过同一个音频输入会话获取。德语原声优先显示其识别原文；英语、中文显示德语译文。
- 在线模式需要用户自己配置服务账号和凭据。应用只在用户明确启用时传送音频；凭据存入 Windows 凭据存储，日志中只记录状态和耗时，不记录凭据或原始音频。默认不保存音频与字幕历史。
- 应用提供可配置的在线使用时长上限，到达后停止在线会话并提示选择本地模式。服务方账单和预算仍须在服务方管理；应用内上限不能视为云账单的绝对封顶。
- 无凭据、网络中断、服务配额或费用限制触发时显示明确状态，保留本地切换入口，不隐式重试产生额外费用。

## 交互与显示

应用包含一个小型设置窗口和托盘菜单。设置窗口负责播放设备、本地/在线模式、语言自动/锁定、字体大小、字幕宽度、透明度、淡出时间和快捷键。字幕条只显示字幕，不显示技术状态；错误与费用状态显示在设置窗口及托盘菜单。关闭设置窗口不退出应用，托盘菜单提供明确退出命令。

首版默认交付“包含 EXE 与模型目录的文件夹”，而不是将数 GB 的模型封入单个 EXE。用户双击其中的 EXE 即可使用；这一包装方式避免每次启动都解压大型模型。发行包需要附依赖和模型许可证信息。

## 验收与阶段

1. **覆盖与采音验证**：在目标德语游戏的无边框全屏模式下，字幕条保持可见、固定、鼠标穿透；能从当前播放设备收到游戏语音。连续运行至少 15 分钟，不崩溃或遮挡游戏操作。若游戏或反作弊限制覆盖层，记录具体游戏和模式，再评估 Windows 原生覆盖方案。
2. **本地德语字幕**：用目标游戏中至少 20 段德语语音检查漏字、重复、误判和延迟；记录从一句话结束到稳定字幕出现的中位数及第 90 百分位。以中位数不超过 3 秒为调优目标；实际数值与配置一同交付。
3. **本地跨语翻译**：分别以至少 20 段英语和中文视频语音检查译文是否忠于原意、自动识别是否正确、原文对照是否可切换。对错误样例留本地测试记录，不自动上传内容。
4. **在线模式与费用边界**：用用户主动配置的测试服务验证模式切换、语言识别、译文、断网处理和应用内时长上限。未配置服务时，确认不会发起在线请求。
5. **EXE 验证**：在不依赖开发终端的情况下启动，检查托盘退出、设置保存、设备切换、模型缺失提示和首次运行说明。

如果第一阶段的置顶字幕条无法在实际游戏中显示，或本地模式无法达到可用速度，应暂停后续开发，向用户展示实测结果并调整窗口技术或模型方案。

## 范围与边界

首版不包含麦克风输入、按应用单独采音、说话人分离、字幕文件导出、词汇卡、自动启动、公开发布或云账号注册。受保护的视频音频、独占全屏游戏及部分反作弊环境可能限制音频回采或覆盖显示；验收只针对用户选定的无边框全屏游戏和普通视频。
